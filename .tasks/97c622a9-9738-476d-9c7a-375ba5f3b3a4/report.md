## 主要问题（按重要程度）

1. **P1/P2 把计划 `K` 当成已完成的 `k_n`，与自己的时间定义尚未闭合。** [框架:64–80] 正确区分了接受、完成和下一观测，也定义了 `v=t+k_n`；但 [框架:140–163] 的 P1/P2 直接用 `K` 选反馈行（P1 为 `K-d`，P2 为第 30 行），P0 的 trace 核对又没有成为后续比较的通过门槛。若 chunk 中断、提前重查或观测延迟，选中第 `r` 行的参考时刻是 `u=t+r`，实际年龄应为 `k_n-r`，不再是声称的 `d`；P2 甚至可能在下一观测前回灌未来预测。最小修正：把 P0 设为后续比较的门槛，逐 query 留存完成/观测时间和 `k_n`；明确只纳入已证实 `k_n=K` 的回合，或按实际 `r=k_n-d` 选行并重新报告实际 `h,d`。这也应适用于真机与异步接口。

2. **P1 仍只能测“联合执行协议敏感性”，不能识别反馈年龄或反馈位置的独立作用。** [框架:80, 144–149, 200–203] 已诚实说明同一 `K` 下改行会同时改变预测提前量，改 `K` 又改变重规划/动作轨迹；但六格没有让其中任一量保持不变，状态误差诊断本身也不能拆开这些原因。因此它不足以支撑“状态消费时间是可迁移设计因素”的机制结论。最小修正：将 P1 与第 7 节的表述限定为固定 checkpoint 的探索性 protocol sensitivity；若要上升为机制主张，预先指定一个保持目标时刻或反馈年龄的配对控制，并在独立训练 checkpoint 上重复，而不是由同一 checkpoint 的多次 eval 推出。

3. **P2 比较的是两套不同的 H 行损失时域，而不单是“是否学习整段轨迹”。** [框架:152–165, 202–203] 两者在第 30 行同为 `phase(t+30)`，但逐帧目标把监督分布在 `t+1…t+50`，重复终点把全部 50 个位置都压在 `t+30`。这同时改变了各 horizon 的预测难度、边界/类别重复权重及对动作共享表示的梯度；[框架:161] 仅列出部分标签分布变化，不能使结果归因于“轨迹本身有价值”。最小修正：若不加一个 endpoint-only 或等效重加权控制，就把问题和结论收窄为“两种完整状态目标构造在末端消费下的比较”；若保留“轨迹监督”的机制结论，则该最小第三控制是必要的。

4. **P3 的“恒定无信息字段”不能单独控制语义信息。** [框架:167–173] 它虽保持字段数/形状，却会改变类别熵、转移频率、状态损失的容易程度以及解码/锁存规则，因而与有效 button 字段相比仍是多重干预。最小修正：事先固定 dummy 的类别支持、边际/转移分布、loss 和约束处理（或用与真实字段统计匹配但对任务无信息的对照）；否则把它明确称作字段设计对照，不把差异解释成 button 语义信息的因果效应。此要求与审计给出的“同形状 dummy + 多 train seeds”缺口一致。[历史审计/rearrange_tokens:111–116]

5. **历史表中的四点 serial K 曲线在限定证据中不可追溯。** [框架:121, 132] 写作 `K15/20/30/50 = 24/42/72.5/46%` 且称为同一固定 checkpoint；但任务限定的审计只明确给出 button checkpoint 的 K30/K50 为 72.5/46%，而 `24/100、26/100` 是另一个 fixed-20 seed42 在 K30 的结果，未给出 42 或一条可核验的四点同 checkpoint 曲线。[历史审计/rearrange_tokens:67–82；shared_memory_timing:95–103；README:35–41] 最小修正：在现有审计范围内删去/标成待核对这条四点数字，或补上同一 checkpoint、train seed、eval seed 和产物路径的受限证据；不要把不同 checkpoint 的数字压成单条 K 曲线。
