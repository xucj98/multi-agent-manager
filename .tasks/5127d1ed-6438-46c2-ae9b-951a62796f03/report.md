## 结论

**可进入用户研究方案讨论，结论为“局部修订”。** 研究问题可理解为：在 action-chunk VLA 中，任务记忆的语义内容如何分别经训练监督、动作条件和执行后的反馈，持续影响下一轮决策。S/P/E 分层、`h/d/Δ` 的自由度限制、以及把 P2 作为“完整目标构造”的比较而非单独时间因素的表述，都足以支持讨论优先级和候选对照。

但新读者还不能只凭主稿准确描述两个锚点实现，也不能将 P1 的结果直接解释为反馈行选择的机制效应；下列修订是进入代码与确认性运行前的门槛，不是要求扩大设计空间。

## 实质发现

1. **已核实锚点尚未成为主稿中的可执行规格。** 位置：§2.1–2.3、§3.2、§5.1。§3.2 对 full/serial 给出高层对照，却以“逐字段获取规则见 schema”指向未在主稿填出的 schema；没有逐字段的 domain、初值/unknown、参考边界、训练/部署输入及 action/state 索引映射，也没有锚点 checkpoint、converter/train/eval 版本和 unknown 项。这个缺口会改变 `t`、第 K 行和缓存值的含义：许可核对的历史记录中，full 是 `g(t)` 输入、`g(t+1)…g(t+H)` tail 监督并按已执行 row 写 cache；fixed-20 serial 则是 `B=g(t-20)`、`C=g(t)`，且 query 级 token 在执行前保存。泛化模板不能替代这些事实。

   最小修正：在正文补两张紧凑的锚点 S/P/E 卡，逐字段列出语义/边界/初始化，列出离线 action 与 state 的索引映射、训练和部署的输入/条件/写读事件，以及具体 artifact 版本和明确的 unknown。完成后才把 P0 标为通过，并据此锁定 P1/P2 的行号解释。

2. **P1 没有定义“反馈行效应”的实际暴露与异常执行处理。** 位置：§3、§5.2，尤其第 165–177 行。`K` 正常完成时第 `K-d` 行的 `h/d` 算法自洽；但选中的 cache 只在下一 query 才影响决策。chunk 内终止的 episode 不会消费该反馈，非终止但实际 `k_n<K` 时也未规定读计划第 `K-d` 行、实际第 `k_n-d` 行，还是重跑/标作协议失败。保留早终止 episode是正确的，但若只报告总体成功率，K 改变的反馈消费比例、query 数和重规划机会会与反馈规则共同进入 K×规则差异。

   最小修正：预先区分全策略成功率（可保留全部 episode）与“发生下一次消费”的暴露诊断；固定非终止 `k_n≠K` 的处理和相应 `u,v,h,d` 计算，并按 arm 报告消费率与 query/暴露次数。这样 P1 可声称端到端协议效应；若要声称反馈选行本身的交互，再使用这些暴露记录限定解释。

3. **P1 的探索与确认性逻辑相互冲突。** 位置：§5.2 第 165、169、177 行，对照 §6 第 235 行和 §7 第 241 行。文本先说在 K=30 探索、再据结果决定是否扩展矩阵，并可复用既有 baseline；同时又要求确认性比较预先固定配置、指标和训练种子。已有 K 曲线本身只是一训练 checkpoint 的探索性证据，且主稿已记录其 evaluator commit 不完全一致。若用同一轮探索选择 K、行规则或任务，再把该结果报告为可重复的交互，结论强度超过设计。

   最小修正：明确把首轮自适应部分标为探索；在查看其结果前，指定独立 checkpoint/任务上的确认性比较、冻结的格点和效应估计，或直接在开始前冻结完整六格。P1 的表述应在完成该确认前限于“对该 checkpoint 的执行协议敏感”。

4. **历史 button×K 数值的 E 条件在主表中少列了一项会改变解释的差异。** 位置：§4 第 126 行、§5.4。主稿正确写了字段数/参数树和 train seed 的问题，却没有在该行说明历史有按钮和无按钮评测采用不同 evaluator commit；允许核对的索引还表明二者是独立 checkpoint。P3 的同形状、统一 evaluator 设计可解决新实验的比较边界，却不会使历史 72.5/39 与 46/37.5 成为干净的交互估计。

   最小修正：在历史覆盖表把 evaluator/实现版本差异列入 E，并把该差异差仅标为生成 P3 的方向性观察；保留 P3 对新训练、同一 evaluator 和训练重复的要求。
