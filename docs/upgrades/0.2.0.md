# 升级到 0.2.0

本页说明从 0.1.0 升级到 0.2.0 时的项目调整。程序安装、实例升级和启动顺序见[安装说明](../install.md#更新)。

## 项目 hooks

`workspace_add` 改由 `MAM_ROOT/.local/hooks/workspace_add` 调用。项目入口可以转发到各 REPO 的 `.local/hooks/workspace_add`；旧 `.local/create_worktree.sh` 可以由 repo 模板继续调用。

下面以模板转发方式为一个 repo 配置入口；在升级后的 MAM_ROOT 中运行，替换 repo 路径：

```bash
repo=/absolute/path/to/PROJECT_ROOT/REPO
mkdir -p .local/hooks "$repo/.local/hooks"
cp templates/hooks/project/workspace_add .local/hooks/workspace_add
cp templates/hooks/repo/workspace_add "$repo/.local/hooks/workspace_add"
chmod +x .local/hooks/workspace_add "$repo/.local/hooks/workspace_add"
```

每个需要创建 worktree 的 repo 都要配置入口，并保留自己的 `.local/create_worktree.sh`。已有自定义入口按[hook 输入与返回](../install.md#输入与返回)调整。

项目需要检查交付、代码合并或产物留存时，配置可选的 `.local/hooks/before_task_archive`。归档使用 `git worktree remove`、`git branch -d`，并删除整个任务 workspace；显式 `--force` 改用对应的强制删除。项目要求和验证结果写入项目 `.local/README.md`，验证方法见[验证项目 hooks](../install.md#验证项目-hooks)。

## 配置与消息

原有 `.mam/env.json` 三个必填项继续使用，新增的超时配置均可省略：

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `HOOK_TIMEOUTS.workspace_add` | 1800 秒 | 创建 workspace 的 hook 时限 |
| `HOOK_TIMEOUTS.before_task_archive` | 60 秒 | 归档前检查的 hook 时限 |

旧 service 未保存消息渠道时使用 `tool`。需要在客户端查看 MAM 消息时，在各实例分别执行：

```text
mam service set message-channel user
```

用 `mam service set message-channel tool` 切回工具渠道。设置保存在当前实例，后续重启继续沿用。

## 命令与工作流程

同步项目的 agent 指令和自动化脚本：

| 操作 | 0.2.0 用法 |
| --- | --- |
| 发布任务要求 | `mam task publish TASK-ID` |
| 执行者首次登记或接手 | `mam task start TASK-ID` |
| 已绑定执行者返工 | 通知原执行者继续工作 |
| 提交报告和附件 | 编辑 `.task/report.md`、`.task/files/`，执行 `mam task report` |
| 暂缓任务 | Manager 执行 `mam task block TASK-ID\|AGENT-PATH --note NOTE` |
| 需要 Manager 反馈 | `mam message send --message TEXT`；需要当前 turn 处理时加 `--immediate` |
| 等待后续工作 | 结束当前 turn，由 service 唤醒；删除旧指令中的 `mam wait` 调用 |
| 新 Manager 接管 | `mam service rebind-manager --note NOTE` |

任务继续执行 MAM_BRANCH 上最新发布的要求。报告草稿记录进度，完成交付后再发布。任务状态自动更新，规则见[任务状态](../designs/task.md#任务状态)；旧记录缺少[提醒计数](../designs/wakeup.md#提醒次数)时从 0 开始。

原 TASK-ID、JOB-ID 和 workspace 继续使用；已有任务可通过 TASK-ID 定位。AGENT-PATH 属于 Codex 协作树，只有能够确认身份时才可用于定位；首次接手时由 `task start` 保存身份并补齐 `.task` 链接。通知缺少可用路径时显示 TASK-ID。

旧 job 的 stopped 在新版按 exited 处理，表示进程已退出；执行者检查结果并归档。归档任务前完成所有 job 的收尾、发布任务文件，并按项目规则整理交付成果。

## 恢复服务

启动 service 前，用 `mam task list` 核对任务；需要暂缓处理的 pending 任务先由 Manager 设置 blocked，再启动服务。

运行 `mam service status` 查看程序、daemon 和数据版本及待办；使用 `mam task list`、`mam job list` 核对保留的任务和进程。仍运行的 job 继续跟踪，停机期间退出的 job 进入收尾流程。按[项目 hook 验证步骤](../install.md#验证项目-hooks)确认新配置后恢复 agent 工作。
